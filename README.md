# momeet (모밋) — 모두의 만남

> 사는 곳도, 몸 상태도 다른 사람들이 **아무도 소외되지 않고** 만날 수 있는 시간과 장소를 찾아 주는 서비스.
> 각자의 **출발역 · 가능한 시간 · 이동 조건**(엘리베이터, 환승, 도보 등)을 모으면, **가장 오래 이동하는 사람의 이동시간이 가장 짧은** 약속 시간과 장소를 추천합니다.

## 1. 바로 확인하기

| | 주소 |
| --- | --- |
| 배포된 웹 | https://momeet-frontend.onrender.com |
| API 문서 (Swagger) | https://momeet-backend.onrender.com/docs |

- **무료 서버라서 오랫동안 쓰지 않으면 잠들고, 첫 접속은 최대 1분 정도 걸립니다.** 화면이 멈춘 것처럼 보여도 잠시 기다려 주세요.
- 서버가 다시 시작되면 **저장된 약속방이 모두 초기화**됩니다(무료 플랜의 한계). 그럴 땐 방을 새로 만들면 됩니다.
- 혼자서 체험하려면 브라우저 창 두 개(하나는 시크릿 창)로 **방장**과 **참여자**를 번갈아 하면 됩니다. 약속방은 2명 이상이어야 추천을 받을 수 있습니다.

## 2. 왜 만들었나

약속 장소를 정할 때 흔히 쓰는 "지도상 가운데"나 "다 같이 덜 걷는 곳"은 한 사람에게 부담이 몰립니다.
이동이 오래 걸리는 사람은 대개 멀리 살거나, 휠체어·유모차 때문에 돌아가야 하거나, 환승이 힘든 사람입니다.

| 장소 | A | B | C | 총합 | 가장 오래 걸리는 사람 |
| --- | --- | --- | --- | --- | --- |
| 1번 역 | 10분 | 20분 | 60분 | 90분 | 60분 |
| 2번 역 | 25분 | 30분 | 35분 | 90분 | **35분** |

총합은 같지만 1번 역은 C 혼자 1시간을 와야 합니다. momeet은 **2번 역**을 고릅니다.

## 3. 핵심 기능

| 기능 | 설명 |
| --- | --- |
| **공평한 시간·장소 추천** | 날짜 × 시간 × 역의 모든 후보를 계산해, 가장 오래 걸리는 사람의 이동시간이 짧은 순으로 추천합니다 |
| **엘리베이터 필수 / 계단 회피** | 엘리베이터가 필요한 사람은 엘리베이터가 있는 역과 환승만 쓰도록 경로를 따로 계산하고, 환승 보행시간을 더 길게(5.7배) 잡습니다. 필수/선호를 구분해 입력합니다 |
| **출발지 → 출발역 도보 반영** | 출발 위치(주소·장소·좌표)에서 출발역까지 걷는 시간(티맵 보행 경로)을 이동시간에 더해 공평성을 계산합니다. 출발 시각도 "집에서 나서는 시각"으로 알려 줍니다 |
| **날짜·시간별 다른 출발역** | "평소엔 신설동, 주말엔 본가 근처 정릉"처럼 예외 출발역을 둘 수 있습니다 |
| **후보가 없을 때 이유 안내** | 조건을 몰래 완화하지 않고, 후보가 하나도 없을 때 날짜별로 이유를 알려 줍니다 (가능한 시간을 안 고른 사람이 있음 / 시간이 안 겹침 / 필수 조건을 동시에 맞출 역이 없음). 일부 경우에는 원인이 "시간이 안 겹침"으로 단순하게 표시될 수 있습니다 |
| **약속 확정까지** | 모집 → 입력 → 추천 → 제안 → 확정. 전원이 동의하면 자동 확정, 거절이 있으면 방장이 다른 후보를 다시 제안합니다 |
| **계정 없이 참여** | 방장이 방을 만들면 서버가 입장 코드를 발급하고, 초대 링크 하나로 참여합니다. 방장은 비밀번호로 다시 들어올 수 있습니다 |
| **개인정보 보호** | 각자의 출발역·경로·조건은 본인에게만 보입니다. 다른 사람에게는 "동의 여부"와 묶음 값만 공유됩니다 |

## 4. 사용 흐름

1. **방 만들기** — 약속 이름, 날짜 범위(1~7일), 방장 닉네임·비밀번호 → 입장 코드와 초대 링크 발급
2. **참여** — 초대 링크로 들어와 닉네임만 입력 (최대 10명)
3. **조건 입력** — 가능한 시간(출발 가능 시간), 출발역, 이동 조건(최대 이동시간·환승·도보·엘리베이터·계단)
4. **추천** — 방장이 모집을 마감하고 추천 실행 → 후보별 최대 이동시간, 내 이동시간·환승, 만남 역 지도
5. **제안·확정** — 방장이 한 곳을 제안하고 전원이 동의하면 확정

## 5. 추천 방식과 효과

### 계산 순서 (`backend/app/core/`)

1. **후보 만들기** — 날짜 × 시작 시각(30분 단위) × 역. 각자 *출발 시각 = 시작 시각 − 이동시간*이 본인이 고른 출발 가능 시간 안에 있어야 하고, 전원이 도착해 **2시간 이상** 함께 있을 수 있어야 합니다.
2. **필수 조건 거르기** — 최대 이동시간·환승·도보·엘리베이터 중 하나라도 못 맞추면 제외합니다. 엘리베이터 정보가 없는 역은 필수 조건을 통과하지 못합니다.
3. **정렬** — ① 가장 오래 걸리는 사람의 이동시간 → ② 선호 조건을 많이 맞추는 순 → ③ 전원 이동시간 합.
4. **고르기** — 같은 날 같은 역은 가장 좋은 시간 1개만, 날짜별 최대 3개.

경로는 역×노선을 하나의 점으로 본 **다익스트라**로 계산해 환승 횟수까지 셉니다 (이동시간 = 역 간 운행시간 + 정차 + 환승 보행 + 환승 대기).

### 비교 결과 (같은 경로 계산에서 장소 고르는 방식만 바꿈)

비교 대상은 **지도 중간지점**(출발역 좌표 평균에서 가장 가까운 역)과 **총합 최소**(전원 이동시간 합이 가장 작은 역)입니다.
아래 수치는 현재 코드(수도권 656개 역)로 직접 다시 계산한 값이며, 같은 입력에서 두 번 돌려 같은 결과가 나왔습니다.

**① 시연 시나리오** — 대학생(신설동), 휠체어 이용자(방화), 교대근무 간호사(잠실), 유모차 부모(수유)

| 방식 | 장소 | 디소공 | 홍길동 | 아무개 | 두루미 | 가장 오래 | 격차 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 지도 중간지점 | 안국 | 22분 | **62분** | 34분 | 29분 | 62분 | 40분 |
| 총합 최소 | 동대문역사문화공원 | 16분 | 52분 | 21분 | 17분 | 52분 | 36분 |
| **momeet** | **홍대입구** | 33분 | 35분 | 38분 | 41분 | **41분** | **8분** |

**② 무작위 그룹 300개** (3~5명, 1~9호선·우이신설선 역에서 무작위 출발)

| 방식 | 가장 오래 걸리는 사람(평균) | 격차(평균) | 누군가 60분 초과 |
| --- | --- | --- | --- |
| 지도 중간지점 | 71.2분 | 43.1분 | 57% |
| 총합 최소 | 72.7분 | 61.7분 | 59% |
| **momeet** | **56.6분** | **29.0분** | **34%** |

- 지도 중간지점 대비 가장 오래 걸리는 사람의 시간이 평균 **14.6분(약 20%) 감소**, 사람 간 격차는 **약 33% 감소**했습니다.
- 300개 중 **97%**에서 지도 중간지점이 momeet보다 가장 오래 걸리는 사람을 더 오래 이동시켰습니다.
- 대신 **전원 이동시간의 합은 총합 최소 방식보다 늘어납니다**(180.5분 대 156.9분). 한 사람에게 몰리던 부담을 나눠 갖는 구조라 생기는 차이입니다.

재현 방법 (`backend/` 폴더에서):

```bash
python -m scripts.demo_scenario                    # 시연 시나리오 추천 결과
python -m scripts.compare_midpoint                 # ① 비교
python -m scripts.compare_midpoint --random 300    # ② 비교
```

## 6. 기술 구성

```
 브라우저 (React) ── HTTPS ──▶ FastAPI 서버 ──▶ SQLite
      │                          ├─ app/core   지하철 경로 · 후보 생성 · 공평성 추천 (순수 로직)
      │                          └─ 티맵 API   출발지→역 보행 경로, 장소·주소 검색 (서버에서만 호출)
      └─ 지도 타일 ◀── OpenStreetMap
```

| 구분 | 사용 기술 |
| --- | --- |
| 프론트엔드 | React, Vite, Tailwind CSS, React Router, axios, Leaflet(OpenStreetMap) |
| 백엔드 | Python, FastAPI, SQLAlchemy, SQLite, bcrypt, httpx, pytest |
| 외부 API | 티맵(SK Open API) — 키는 서버 환경 변수에만 두고 브라우저에는 노출하지 않음 |
| 배포 | Render (`render.yaml` 한 파일로 백엔드 Web Service + 프론트 Static Site 동시 배포) |

## 8. 로컬에서 실행하기

**백엔드** (Python 3.14에서 개발·테스트)

```bash
cd backend
python -m venv .venv
.venv\Scripts\activate            # macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
copy .env.example .env            # macOS/Linux: cp .env.example .env
uvicorn app.main:app --reload     # http://localhost:8000/docs
```

**프론트엔드**

```bash
cd frontend
npm install
copy .env.example .env            # VITE_API_URL=http://localhost:8000
npm run dev                       # http://localhost:5173
```

- 티맵 키(`TMAP_APP_KEY`)는 선택입니다. **없어도 서버와 테스트는 그대로 동작**하며, 출발지→역 도보는 직선거리 추정으로 계산하고 장소 검색만 쓸 수 없습니다.
- 시연용 방을 미리 만들려면 `python -m scripts.seed --yes` (단계별 약속방 5개, 방장 비밀번호 `demo-password`).

## 10. 개인정보와 보안

- **비밀번호·토큰:** 방장 비밀번호는 bcrypt로 해시하고, 참여 토큰은 해시로만 저장합니다. 약속방마다 토큰이 달라 다른 방에서는 통하지 않습니다.
- **타인 정보 비공개:** 추천 결과 원본에는 모든 참여자의 경로가 있어 서버에만 두고, 조회 응답에는 **요청한 본인의 경로만** 내려갑니다. 후보가 없을 때의 사유도 이름 없이 인원수만 보여 줍니다.
- **출발 위치:** 좌표는 약 100m 단위로 반올림해 저장하고, 주소로 입력해도 **주소는 저장하지 않으며**, 좌표는 본인 조건 조회 외의 응답에 나오지 않습니다.
- **무차별 대입 방어:** 입장 코드·방장 비밀번호를 연속으로 틀리면 일정 시간 막습니다.
- **키 관리:** API 키는 서버 환경 변수에만 두고 저장소에 올리지 않습니다 (`.env`는 `.gitignore`).

## 11. 데이터 출처와 가정

- 서울교통공사: 역간거리·소요시간, 환승역 거리, 역별 승강설비현황(엘리베이터) / 서울 열린데이터광장: 역사 좌표, 지하철역 엘리베이터 위치 / 공공데이터포털: 한국철도공사 역별 승강설비 현황, 인천교통공사 엘리베이터 설치현황 / 국가철도공단: 9호선·우이신설선 및 수도권 광역철도·경전철 역간거리
- 지도 © OpenStreetMap contributors, 보행 경로·장소 검색은 티맵(SK Open API)
- 주요 가정: 역마다 정차 30초, 환승 대기 3분, 엘리베이터가 필요한 사람의 환승 보행시간 5.7배(출처: '모두의 지하철 프로젝트'(2025) 실증조사 — 휠체어 이용자 환승 평균 19분 대 비장애인 3.3분), 서울교통공사 1~8호선 밖 구간은 거리로 환산한 추정 시간
- 자세한 출처·근거·한계는 [backend/docs/algorithm.md](backend/docs/algorithm.md)

## 12. 구현 현황과 한계

### 현재 구현 상태

| 항목 | 상태 |
| --- | --- |
| 약속방 생성 · 입장 코드 · 초대 링크 · 방장 재접속 | 구현, 배포 환경에서 확인 |

| 출발지 장소·도로명 주소 검색 (`GET /places`, 최대 5건) | 서버 구현, 화면 연동은 아직 |
| 엘리베이터 **가동 상태**(고장 여부) 반영 | 미구현 |
| 만남 역 → 실제 약속 장소 안내 | 미구현 |

### 한계 (솔직하게)

- **엘리베이터 정보 범위:** 수도권 656개 역 중 엘리베이터 유무를 확인한 곳은 569개 역(있음 563, 없음 6)이고, 민자·경전철 등 87개 역은 정보가 없습니다. **정보가 없는 역은 엘리베이터 필수 조건에서 만남 장소로 추천되지 않습니다.** 코레일 자료는 2023.01 기준이라 그 뒤에 설치된 엘리베이터는 빠져 있을 수 있습니다.
- **"있다"는 뜻:** 역에 엘리베이터가 있다는 것이지 지금 작동한다는 뜻이 아닙니다. 계단 회피는 엘리베이터 필수와 같은 규칙이며, 승강장↔출구 전체 동선이 계단 없이 이어지는지까지는 보장하지 않습니다.
- **이동시간은 추정입니다:** 시간표가 아니라 평균 소요시간 기준이고, 급행·막차는 반영하지 않습니다. 서울교통공사 1~8호선 밖 구간은 거리로 환산한 값이라 먼 거리는 실제보다 길게 나옵니다.
- **지하철만:** 버스 등 다른 이동 수단과 역 주변 장소(상권)는 고려하지 않습니다.
- **정렬 기준의 특성:** 가장 오래 걸리는 사람을 먼저 보기 때문에, 1분 차이로 전체 합이 훨씬 큰 곳이 앞설 수 있습니다.
- **서버:** 무료 플랜이라 재시작 시 데이터가 초기화되고, 최대 조건의 추천 계산은 수십 초가 걸립니다(비동기 처리 미적용).
